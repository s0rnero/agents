# Agents Harness

Generic `.agents` harness to boot the same agent workflow in every repository. Inspired by the `.agents` systems of **Khatarsis** (Vue 3, v3.3) and **Alytos** (Java/Spring, v1.0): same conversational flow, same authorization gates and same plan lifecycle in every repo, without reinventing the system per project.

## What it offers

- **Single source of the workflow**: Orchestrator -> Enrichment -> Executor, identical in every repo.
- **Explicit gates**: "enrich the plan" (`PENDING -> ENRICHED`) and "execute the plan" (`READY -> EXECUTED`). No ambiguous phrase ("continue", "proceed", "investigate") authorizes transitions.
- **Plan lifecycle**: `PENDING -> ENRICHED -> READY -> EXECUTED -> CLOSED`, with an MD plan persisted in `.agents/plans/` for broad requests. Plans are the project's **persistent memory**: they are never deleted and every change is documented in the plan before being executed.
- **Definition of Done**: no plan moves to `CLOSED` without meeting the DoD (verification, hygiene, memory entry) reviewed by the Reviewer role.
- **Architecture decisions (ADR)**: permanent registry in `.agents/decisions/`, complementary to plans.
- **Stack skills via autoskills**: `npx autoskills` scans the repo, detects the technologies and installs the curated skills from the audited registry into `.agents/skills/`.
- **Generic operating rules** (Git, deletion, scope, scripts, secrets) identical in every repo.
- **Core/stack separation**: the workflow does not change; each repo only adapts its profile, standards and design.
- **Command-based install and update**: `setup.mjs` integrates the harness into any project and `update` brings harness changes without overwriting local adaptations or plans.
- **Multi-agent compatibility**: the install generates `AGENTS.md`, `CLAUDE.md`, `.cursorrules` and `copilot-instructions.md` at the root pointing to `.agents/`.
- **Language policy**: normative content is written in English; user plans follow the language the user writes their prompts in (RULES.md 0.14).

## Structure

```text
.agents/
|-- AGENTS.md                      # Central index (project profile + system)
|-- RULES.md                       # Generic operating rules
|-- CODING_STANDARDS.md            # Code conventions (adapt per repo)
|-- DESIGN.md                      # Architecture and design (adapt per repo)
|-- WORKFLOW.md                    # Current flow + gates + DoD + plan cycle
|-- PLANS.md                       # Plan ownership (persistent memory)
|-- manifest.json                  # Harness version and lists (install/update)
|-- plans/                         # Project plans (persistent memory)
|-- decisions/                     # Architecture decisions (ADR, permanent)
|-- templates/                     # Templates: plan.md and adr.md
|-- orchestrator/instructions.md   # Orchestrator role
|-- subagents/                     # Enrichment, Executor and Reviewer (DoD)
|-- skills/README.md               # Skills registry + autoskills
`-- bootstrap/INSTALL.md           # Install and update guide
scripts/
|-- setup.mjs                      # Installs/updates the harness by command (install/update, --from)
|-- verify.mjs                     # Health check of the installed harness
`-- install.sh                     # setup.mjs wrapper with bash fallback
AGENTS.md, CLAUDE.md, .cursorrules, .github/   # Root compatibility layer (generated by the install; present here as an example)
package.json                       # npm package with binary: npx agents-setup-sorno
```

## Quick start

### Short command (npx/bunx)

The harness is an npm package with a binary (`agents-setup-sorno`). Once published:

```bash
npx agents-setup-sorno ../repo-name
bunx agents-setup-sorno ../repo-name
```

Before publishing, activate it locally with `npm link` (or `bun link`) from this repo, and then `agents-setup-sorno <repo>` works from any folder.

### Install into any project (no copy/paste, no cloning)

```bash
node scripts/setup.mjs ../repo-name            # install from this repo
node scripts/setup.mjs ../repo-name --from https://github.com/<user>/<repo>.git
node scripts/setup.mjs                         # uses the current directory
```

It installs the core into `.agents/`, detects the stack, fills the `AGENTS.md` profile, generates the root compatibility layer (`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `copilot-instructions.md`) and runs autoskills (preview by default; `--skills` to install). It registers the origin in `.agents/manifest.json`.

### Bring harness changes later

```bash
node scripts/setup.mjs ../repo-name update               # uses the registered origin
node scripts/setup.mjs ../repo-name update --from <url>  # from another source
```

It updates only the core; it never overwrites adapted `AGENTS.md`, `CODING_STANDARDS.md`, `DESIGN.md`, plans, decisions or skills.

### Verify

```bash
node scripts/verify.mjs ../repo-name   # health check: core, plans, ADRs, compat, skills
```

### Lightweight install (fallback)

```bash
bash scripts/install.sh ../repo-name          # uses setup.mjs when Node is available
bash scripts/install.sh ../repo-name --skills # also installs detected skills
```

Full details in `.agents/bootstrap/INSTALL.md`.
